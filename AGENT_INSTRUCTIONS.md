# Operating protocol

Read the whole brief. Initialize with `bin/autoresearch init` only after establishing a meaningful, safe empirical question and an explicit bounded resource policy. If missing or contradictory, record a blocker and stop. Policy extraction is an agent judgment, not a security boundary; deterministic checks enforce only recorded fields. Never revise policy silently.

Loop: recover state, brief snapshot/hash, policy, protocol, ledger, budget, and jobs; propose a justified hypothesis, changed/fixed variables and resource request; create isolated experiment directory and manifest with command, hashes, inputs, seeds and parent; validate; execute only through `bin/research-job`; preserve logs; validate nonempty measured result; analyze controls/uncertainty; record failures too; atomically update state/ledger/findings/report and next step. Baseline precedes comparisons. Keep evaluation stable or version protocol. Continue until budget/stop/blocker/allocation end. Do not ask interactive research questions; record blockers. Bound retries. Never claim computation without executed output.

Commands: `bin/autoresearch check`, `init`, `status`, `start`, `stop`, `report`, `smoke`, `submit`, `usage`, `review`, `reopen`, `loop`. Prefer an interactive session. The person pastes `loop/prompts/interactive.md` and keeps this process open. `start` prints that reminder. Jobs must use research-job; default is local only in an appropriate allocation. Separate Slurm submissions require explicit brief authorization and complete validated policy. Reconcile active jobs on resume; never duplicate them.

Write `documents/paper.md` for each version. After a review exists, also write a new `documents/response.md`. Those files are what the strong model sees. Keep experimental records in the campaign directory. When the version is written, run `bin/autoresearch submit` and wait for it to exit. It calls the strong model, syncs git, and writes `documents/REMARK.md` when three reviewers accept or `documents/REVIEW.md` otherwise. One reviewer reads the manuscript first. A rejection is stored as usual. An acceptance is sent to two further reviewers, who do not see the earlier review, and both must accept before the work can finish. If either does not, the three reviews are combined into `documents/REVIEW.md`. The next version starts with one reviewer again, and the two further reviewers are called only after that reviewer accepts. Then sleep 600 seconds and read the file the command names. Stop on accept, or when the command reports no significant progress across the last three versions. Leave git push, git pull, and git reset to `submit`.

When the human is not satisfied with an accepted or stalled round, they replace `RESEARCH_BRIEF.md` and paste `loop/prompts/interactive_reopen.md`. Run `bin/autoresearch reopen` and wait until it exits. It archives the finished round under `documents/rounds/` and pins the new brief. It does not call the strong model and it does not sync git. When it blocks, stop and leave the finished round in place. After it reopens, write a new `policy.json` from the new brief, run `bin/autoresearch init`, and continue with `documents/paper.md`, `bin/autoresearch submit`, and sleep 600. Leave the archived round and the previous campaign directory in place.

`bin/autoresearch loop` is the unattended alternative. Only when that command started this process, finish one manuscript version and exit. The loop calls the strong model after that exit. The unattended loop does not adopt a new brief.
